## 1. Executive Summary & Evidence: Is Lovable Cloud Supabase-Based?

**Yes, Lovable Cloud is 100% Supabase-based.** The codebase contains unambiguous architectural evidence that Lovable Cloud is a hosted wrapper around standard Supabase services (PostgreSQL, GoTrue Auth, Storage API, PostgREST, and Realtime):

1. **Supabase Configuration**:
   - `supabase/config.toml` exists in the repository root with `project_id = "naflzehzkerpszwgfadf"`.
2. **Supabase Client SDK & Types**:
   - `package.json` includes `@supabase/supabase-js` (`^2.49.1`).
   - `src/integrations/supabase/client.ts` instantiates standard Supabase clients (`createClient<Database>`) with publishable keys and custom headers.
   - `src/integrations/supabase/client.server.ts` instantiates service-role Supabase clients bypassing RLS.
   - `src/integrations/supabase/types.ts` is an auto-generated TypeScript schema export (580+ lines) defining PostgreSQL tables, enums, composite types, and RLS metadata directly in the format generated by `supabase gen types typescript`.
3. **Database Migrations & PostgreSQL Schema**:
   - `drizzle/migrations/0000_migration.sql` contains PostgreSQL DDL executing directly against Supabase:
     - Foreign keys referencing `auth.users(id)` with cascading deletes.
     - Row-Level Security (RLS) policies using `auth.uid()`.
     - Auth trigger `on_auth_user_created` hooking into `auth.users` to provision profiles and assign user/admin roles.
     - Storage bucket policies on Supabase schema `storage.objects` with helper `storage.foldername(name)`.
4. **Environment Variables**:
   - `.env` specifies `SUPABASE_PROJECT_ID`, `SUPABASE_PUBLISHABLE_KEY`, and `SUPABASE_URL`.
5. **Auth & Infrastructure Middleware**:
   - `src/integrations/supabase/auth-attacher.ts` and `auth-middleware.ts` integrate Supabase JWT claims verification (`supabase.auth.getClaims`).
   - `src/integrations/supabase/previewAuthStorage.ts` brokers sessions specifically between the Lovable preview iframe and Supabase Auth.

**Migration Conclusion**: Because the existing data schema, auth model, and storage policies are already architected for Supabase, migrating from Lovable Cloud to an independent local Supabase stack (`supabase start`) requires zero schema rewrites. We only need to replace Lovable's proprietary proxy layer (preview auth, Lovable AI gateway) with standard local Supabase CLI configurations, direct AI provider API calls in Supabase Edge Functions, and direct Supabase client initialization.

## 4. Storage Architecture & Media Lifecycle

### 4.1 Bucket Specification
- **Name**: `media`
- **Visibility**: Private (`public = false`)
- **Folder Pattern**: `<user_id>/<submission_id>/...`
- **Artifacts Stored**:
  - Original media: `<user_id>/<submission_id>/original.[mp4|jpg|png]`
  - Extracted frames: `<user_id>/<submission_id>/frames/frame_000.jpg`, etc.
  - Extracted audio: `<user_id>/<submission_id>/audio.wav`

### 4.2 Storage RLS Policies
Enforced on `storage.objects`:
- `own media read`: `bucket_id = 'media' AND (storage.foldername(name))[1] = auth.uid()::text`
- `own media write`: `bucket_id = 'media' AND (storage.foldername(name))[1] = auth.uid()::text`
- `own media delete`: `bucket_id = 'media' AND (storage.foldername(name))[1] = auth.uid()::text`

### 4.3 URL Access
Client requests media playback via signed URLs created with `supabase.storage.from('media').createSignedUrl(path, 3600)`.

### 4.4 24-Hour Media Retention Policy
A database function triggered via `pg_cron` (or scheduled invocation) searches for submissions analyzed > 24 hours ago where `media_deleted_at IS NULL`:
- Deletes storage files in the submission folder using the Supabase Storage API (`supabase.storage.from('media').remove(...)`).
- Sets `media_deleted_at = now()`.
- Retains all findings, metadata, transcripts, and SHA-256 hashes permanently.
- The user can also trigger immediate deletion via the UI ("Delete media" action).

## 5. Analysis Pipeline in Supabase Edge Functions

### 5.1 Architecture & Pipeline Stages

In place of Lovable AI gateway server functions, we use modular Supabase Edge Functions (`supabase/functions/analyze/`):

```
[Client Upload] 
       │ (original file + client-extracted frames + caption + metadata)
       ▼
[Edge Function: analyze]
       │
       ├─► Stage 1: Transcribe
       │     Calls OpenAI Whisper API / Audio Transcription with timestamp granularities (`word` / `segment`)
       │     Saves transcript & segments to `transcripts` table
       │     Updates submission `current_step = 'deterministic'`, `progress = 40`
       │
       ├─► Stage 2: Deterministic Rules
       │     Checks metadata & transcript regex:
       │     - MAW-01: Is paid ad? Look for disclosure ("إعلان", "برعاية", "#إعلان") in first 5s or caption
       │     - MAW-03: Is paid ad? Verify `has_written_contract == true`
       │     - MAW-04: Is paid ad? Verify `mawthooq_license_no` present
       │     - AI-01: If `ai_used == true`, check disclosure in caption/first 5s
       │     Saves findings to `findings` table
       │     Updates submission `current_step = 'llm'`, `progress = 70`
       │
       ├─► Stage 3: LLM Visual & Content Analysis
       │     Constructs multi-modal payload: transcript + frames (base64 or signed URLs) + caption
       │     Appends rule prompts from `rules.llm_instructions`
       │     Calls Anthropic Claude (e.g. `claude-3-5-sonnet-20241022` default) or OpenAI (`gpt-4o`)
       │     Enforces strict JSON schema output:
       │     `{ findings: [{ rule_code, severity, t_start, t_end, evidence_type, evidence_text, explanation_ar, fix_ar, confidence }] }`
       │
       ├─► Stage 4: Post-Processing & Deduplication
       │     - Drop findings with unknown rule codes
       │     - Downgrade weak evidence (< 0.7 confidence) to "warning"
       │     - Deduplicate with deterministic findings within 3s window
       │     Updates submission `current_step = 'merge'`, `progress = 90`
       │
       └─► Stage 5: Final Evaluation & Status
             - If any violation -> `overall_status = 'needs_fixes'`
             - Else if warnings only -> `overall_status = 'review'`
             - Else -> `overall_status = 'ready'`
             - Generates compliance log hash
             - Sets `status = 'done'`, `progress = 100`, `analyzed_at = now()`
```

### 5.2 Resumability & Timeouts
To respect Edge Function execution limits, each step updates `current_step`, `progress`, and writes incremental output into `analysis_runs.step_outputs`. If a step errors or times out, the function can be reinvoked with the submission ID to resume from the last completed stage.

### 5.3 Model & Version Auditing
Every run persists:
- `llm_model`: from env (e.g., `claude-3-5-sonnet-20241022` or `gpt-4o`)
- `asr_model`: from env (e.g., `whisper-1`)
- `prompt_version`: `v1`
- `rulebook_version`: `2026.10-a`

### 5.4 Demo Mode
When API keys (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) are omitted or when a demo submission is tested, the pipeline returns instant mock results matching the seed reports without failing.

## 6. Browser-Side Logic to Keep Unchanged

The following client-side operations will be retained in the frontend without modification:
1. **Frame Extraction**: Canvas-based extraction from HTML5 Video element (1 JPEG every 2s, max 45 frames, plus first and last frame with exact timestamps).
2. **SHA-256 Hashing**: Browser `crypto.subtle.digest('SHA-256', buffer)` executed prior to upload for tamper-proof compliance logs.
3. **Audio Extraction**: WebAudio / AudioContext downsampling to WAV for video files where bandwidth optimization is beneficial.
4. **i18n & RTL Handling**: `src/lib/i18n.tsx` maintaining Arabic as primary locale and supporting English toggle.
5. **Print Compliance Log**: Native `window.print()` triggered from the `Log` screen with print-tailored CSS stylesheets.

## 8. Risks and Open Questions

### 8.1 Risks & Mitigations

1. **Vite Build Configuration (`@lovable.dev/vite-tanstack-config`)**:
   - *Risk*: `vite.config.ts` imports `@lovable.dev/vite-tanstack-config`. Removing it abruptly might break TanStack router compilation or Tailwind bundling.
   - *Mitigation*: We will inspect the plugin's configuration before decoupling it, ensuring standard `@vitejs/plugin-react`, `tailwindcss`, and `tanstack/router-plugin` run cleanly without Lovable dependencies.
2. **Edge Function Timeout on Video Processing**:
   - *Risk*: Transcribing audio and running multi-modal LLM frame inspection on 90s clips could exceed free Edge Function runtime limits (e.g. 60–150s).
   - *Mitigation*: We break the pipeline into distinct, resumable steps (`transcribe` -> `deterministic` -> `llm` -> `merge`), update `progress` in the database at each step, and support step-by-step chaining.
3. **Demo User Creation in Local GoTrue**:
   - *Risk*: `auth.users` cannot be populated reliably with plain passwords via static SQL seed because GoTrue manages bcrypt password hashes and internal user IDs.
   - *Mitigation*: We provide `scripts/seed-demo-user.ts` which uses the Supabase Admin API (`supabase.auth.admin.createUser`) with the service role key to reliably create `demo@saleem.app` / `demo123456`.

### 8.2 Clarifications & Decisions for User Review

1. **Frontend TanStack Start vs Vite SPA**:
   - The frontend currently has TanStack Start configuration files (`start.ts`, `server.ts`) but only one route (`/`).
   - *Recommendation*: Keep using the standard Vite dev server without complex SSR, directly using `@supabase/supabase-js`.
2. **Realtime vs 2-Second Polling**:
   - Local Supabase Realtime works out-of-the-box with `supabase start`. We will implement Realtime channel subscription for the `Processing` screen with an automatic fallback to 2-second polling to guarantee maximum reliability.
3. **Model Selection**:
   - Default LLM: `claude-3-5-sonnet-20241022` (Anthropic).
   - Default ASR: `whisper-1` (OpenAI).
   - Both configurable via `.env` in `supabase/functions/`.
